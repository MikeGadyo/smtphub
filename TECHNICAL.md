# Руководство SMTPHub

Версия 1.0.0-beta2. Автор: mikegadyo. Установка описана в [README](README.md).

## Настройки подключения

Названия SMTP-полей берутся из установленного MODX. Параметры подключения укажите по инструкции вашего SMTP-провайдера.

| Поле | Назначение |
| --- | --- |
| Название | Понятная подпись, например «Основной». На порядок отправки название не влияет. |
| SMTP хосты | Один адрес, например `smtp.example.com`, без протокола, порта и пути. Поддерживаются DNS-имена и IPv4. |
| SMTP номер порта | Порт от 1 до 65535. Обычно SSL использует 465, TLS (STARTTLS) — 587. |
| Шифрование SMTP / SMTPS | SSL, TLS (STARTTLS) или без шифрования. |
| SMTP аутентификация | Использовать логин и пароль. При включённой авторизации оба поля обязательны. |
| SMTP пользователь | Логин, выданный провайдером; он не всегда совпадает с адресом отправителя. |
| SMTP пароль | Пароль подключения. Пустое поле при редактировании сохраняет прежний пароль. |
| Очистить пароль | Удаляет сохранённый пароль. При включённой авторизации сохранить запись без пароля нельзя. |
| SMTP время ожидания, сек. | Таймаут отдельной операции: 1–60 секунд, по умолчанию 5. |
| Авто TLS для SMTP | Разрешает переход на TLS, если сервер его предлагает. |
| Email отправителя | Необязательно. Пустое поле сохраняет From и Sender сайта. Заполненное заменяет оба адреса при отправке через этот сервер. |
| Имя отправителя | Необязательно. Пустое поле сохраняет имя, заданное сайтом. Заполненное заменяет только имя «От кого». |
| Состояние | Участвует ли сервер в отправке. Выключенный сохраняет настройки и место в списке. |

### Шифрование и авто TLS

- **SSL:** соединение шифруется с начала подключения. Название соответствует режиму `ssl` в MODX/PHPMailer; версия протокола согласуется с сервером.
- **TLS (STARTTLS):** переход на TLS обязателен, независимо от флажка авто TLS.
- **Без шифрования, авто TLS включён:** TLS включается, если сервер предлагает STARTTLS. Если не предлагает, соединение может остаться незашифрованным.
- **Без шифрования, авто TLS выключен:** автоматического перехода на TLS нет.

Ошибка TLS или недействительный сертификат завершают попытку подключения; пакет пробует следующий сервер. Шифруется соединение от сайта до SMTP-сервера.

### Отправитель для каждого сервера

Например, в записи Яндекса можно указать `site@yandex.ru`, а в записи Mail.ru — `site@mail.ru`. При переключении SMTPHub подставит адрес выбранной записи. Оба сервиса должны разрешать соответствующие адреса. SMTP-логин не подставляется вместо email автоматически.

Если сайт отправляет от общего адреса, например `info@example.com`, оставьте поля пустыми и разрешите этот адрес на всех SMTP. Сохраняется также отдельный Sender/emailReturnPath, если его задал сайт. При заполненном email отправителя SMTPHub использует его и для From, и для Sender. Reply-To, получатели, вложения и содержимое письма сохраняются. Имя можно переопределить независимо от адреса.

При выборе сервера письмо формируется и подписывается заново до начала передачи. Если сайт самостоятельно подписывает письма DKIM, его настройки домена и ключа должны подходить выбранному отправителю. После отправки исходные параметры почтового объекта восстанавливаются для следующего письма.

### Таймаут и пауза после сбоя

**Таймаут** задаёт, сколько ждать во время отдельной SMTP-операции. Маленькое значение ускоряет переход к резервному, но может отсечь медленный исправный сервер. Большое даёт серверу больше времени, но увеличивает ожидание при сбое. Отправка состоит из нескольких операций, поэтому таймаут 5 секунд не означает, что всё письмо отправится за 5 секунд.

**Пауза после сбоя** — общая настройка от 1 до 86400 секунд, по умолчанию 60. После отказа основной сервер пропускается на это время, а резервный пробуется сразу. Новые письма во время паузы обходят основной. После паузы он снова пробуется при очередной отправке; фонового таймера нет. У каждого сервера свой отсчёт. Изменение длительности применяется к новым сбоям.

## Порядок и действия

Первым используется верхний включённый сервер, который не находится в паузе. Перетаскивайте строки за любое место, кроме кнопок действий. Порядок сохраняется сразу. Для клавиатуры сфокусируйте значок перемещения и используйте стрелки вверх/вниз.

Новый сервер добавляется в конец. Значок питания включает или выключает запись: зелёный — включена, серый — выключена. В меню **⋮** доступны:

- **Редактировать:** изменить подключение. Также можно дважды щёлкнуть по строке.
- **Сделать копию:** создать независимую запись в конце списка с теми же параметрами, паролем и состоянием. Результат доступности не копируется.
- **Использовать в MODX:** после подтверждения заменить глобальные SMTP-настройки выбранным подключением, включая пароль, и включить штатный SMTP. Переопределение email/имени из записи SMTPHub не переносится: отправитель сайта и состояние SMTPHub сохраняются. Для отправки через системные настройки выключите SMTPHub отдельно.
- **Удалить:** после подтверждения убрать запись из списка.

Если другой пользователь изменил список одновременно с вами, обновите его и повторите действие.

## Импорт настроек SMTP

Кнопка **Импорт настроек SMTP** копирует глобальные SMTP-настройки MODX. Настройки пользователей и контекстов не импортируются. Установка и включение пакета не запускают импорт автоматически.

Копируются адрес, порт, шифрование, авторизация, логин, пароль, таймаут и авто TLS. Несколько хостов через `;` превращаются в отдельные записи. Префиксы `ssl://`/`tls://` и порты в адресах учитываются. В MODX 2 используется `mail_smtp_prefix`, в MODX 3 — `mail_smtp_secure`.

Подключения включаются и добавляются в начало списка. Полностью совпадающие записи повторно не создаются: существующая запись переносится в начало и включается. Системные настройки сохраняются; SMTPHub нужно включить отдельно.

Новые записи после импорта получают пустые поля отправителя. Повторный импорт сохраняет ранее заданные переопределения совпадающих записей. Копирование сервера сохраняет его email и имя отправителя.

Пустые настройки и стандартный `localhost:25` без авторизации пропускаются. Некорректные данные прерывают импорт целиком. Например, таймаут выше 60 секунд нужно изменить или добавить подключение вручную. Импорт не проверяет соединение.

## Проверка доступности

Кнопка **Обновить** перечитывает список и последовательно проверяет включённые подключения: соединение, SSL/STARTTLS и авторизацию. Письмо при этом не отправляется. Проверка работает и при выключенном SMTPHub, не меняет порядок и не сбрасывает паузы после сбоя.

Колонка **Доступен** показывает результат с датой, например `Да (13.10.26)` или `Нет (13.10.26)`. Он сохраняется после перезагрузки страницы до следующей проверки. Выключенные записи не проверяются. Если параметры изменились, прежний результат помечается `*`. Подсказка показывает пояснение и точное время; дата отображается в часовом поясе браузера.

«Ошибка проверки» означает проблему с запросом, а не обязательно недоступность SMTP. Предыдущий результат в базе сохраняется. Успешная проверка соединения не гарантирует доставку письма.

## Отправка и хранение

SMTPHub использует общий штатный почтовый сервис MODX на событии `OnMODXInit`, сохраняя его API. Файлы ядра не изменяются. Прямой вызов `mail()`, отдельный PHPMailer и сторонние почтовые сервисы обходят пакет.

Отправка синхронная. Искусственной задержки нет; при сбое текущая отправка ждёт неудачную попытку и затем переходит к резервному. Для каждого письма открывается новое соединение. Изменённые настройки применяются в следующих запросах.

Переключение выполняется при ошибке подключения, TLS или авторизации. После начала SMTP-транзакции письмо на другом сервере не повторяется: предыдущий сервер уже мог его принять. Если все подключения недоступны, отправка завершается ошибкой. Очереди и автоматического перехода на штатный SMTP нет. Выбранный отправитель должен быть разрешён на используемом сервере.

Записи хранятся в таблице `{table_prefix}smtphub_servers`, результаты доступности — в `{table_prefix}smtphub_servers_availability`. Пароли шифруются AES-256-GCM, ключ находится в `core/config/smtphub.key.php`. Для резервной копии и переноса сайта сохраняйте базу и ключ вместе. Без прежнего ключа сохранённые пароли восстановить нельзя. Каталог `core/config/` должен быть закрыт от HTTP-доступа.

Паузы хранятся в `core/cache/smtphub/`. Очистка этого каталога сбрасывает паузы. Для нескольких веб-узлов нужен общий файловый кеш, если состояние должно быть общим.

Обновление сохраняет серверы, пароли, ключ и настройки. Для возврата к штатной отправке выключите SMTPHub и сохраните настройки. При удалении пакета его таблицы, ключ и файлы сохраняются для восстановления данных. Ранее перенесённые в MODX SMTP-настройки автоматически не восстанавливаются.

## Сборка из исходников

Нужны PHP с ZipArchive и исходники MODX Revolution 2.8 с xPDO. Передайте путь к каталогу `core`:

```shell
php _build/build.transport.php /path/to/modx-2.8/core
```

База данных для сборки не требуется. Архив создаётся в `_packages/`; существующий выпуск не перезаписывается. Перед повторной сборкой перенесите прежний архив и одноимённый каталог в резервную папку. Версия и автор заданы в `core/components/smtphub/version.php`.
